# Ответы на контрольные вопросы к лабораторной работе №1

Ниже — развёрнутые ответы на все 22 вопроса по теме «Основы логического программирования. Поиск с возвратом». Ответы опираются на материал методички и стандартное поведение SWI-Prolog.

## 1. Дайте определение понятиям «факт» и «правило вывода». Приведите по три примера.

**Факт** — это утверждение, которое всегда истинно и не требует доказательства. Факт — это предикатное предложение без тела (без хвостовой части).

**Правило вывода** — это утверждение, истинность которого зависит от истинности других утверждений (подцелей). Правило имеет голову и тело, соединённые знаком `:-`.

**Примеры фактов:**

```prolog
man('Иван').                    % Иван — мужчина
parent('Андрей', 'Сергей').     % Андрей — родитель Сергея
married('Пётр', 'Анна').        % Пётр женат на Анне
```

**Примеры правил вывода:**

```prolog
% 1. Брат — мужчина, у которого общий родитель с другим человеком
brother(X, Y) :-
    man(X),
    parent(P, X),
    parent(P, Y),
    X \= Y.

% 2. Бабушка — женщина, являющаяся родителем родителя
grandmother(X, Y) :-
    woman(X),
    parent(X, Z),
    parent(Z, Y).

% 3. Тесть — отец жены
father_in_law(X, Y) :-
    man(X),
    married(Y, W),
    parent(X, W).
```

## 2. Перечислите составные части правила вывода.

Правило вывода состоит из двух частей, разделённых знаком `:-`:

1. **Голова (head)** — предикат, который доказывается. Записывается слева от `:-`. Например, `brother(X, Y)`.
2. **Тело (body) / хвостовая часть** — список подцелей (целей), которые нужно доказать, чтобы доказать голову. Записывается справа от `:-`, цели разделяются запятыми. Например, `man(X), parent(P, X), parent(P, Y), X \= Y`.
3. **Точка** в конце предложения — обязательный элемент синтаксиса.

Формат:

```
голова :- подцель1, подцель2, ..., подцельN.
```

---

## 3. Как толкуется условное обозначение «:-»?

`:-` читается как **«если»** (или «при условии, что»). Конструкция

```prolog
H :- B1, B2, ..., Bn.
```

означает: **«H истинно, если истинны B1, B2, …, Bn»**. То есть голова правила доказуема при условии, что доказаны все подцели тела.

Например:

```prolog
brother(X, Y) :- man(X), parent(P, X), parent(P, Y), X \= Y.
```

Читается: «X — брат Y, **если** X — мужчина, **и** у X и Y есть общий родитель P, **и** X не равен Y».

## 4. Что означают символы «,» и «;» в хвостовой части правила?

- **Запятая `,`** — логическое **И** (конъюнкция). Все подцели, разделённые запятыми, должны быть истинны **одновременно**. Если хотя бы одна ложна — всё тело ложно.

```prolog
brother(X, Y) :- man(X), parent(P, X), parent(P, Y), X \= Y.
% Все четыре условия должны выполниться
```

- **Точка с запятой `;`** — логическое **ИЛИ** (дизъюнкция). Достаточно, чтобы была истинна **хотя бы одна** из альтернатив.

```prolog
parent_or_guardian(X, Y) :- parent(X, Y) ; guardian(X, Y).
% X — родитель Y ИЛИ опекун Y
```

Комбинировать можно:

```prolog
relative(X, Y) :- parent(X, Y), man(X) ; parent(X, Y), woman(X).
% X — родитель Y и мужчина, ИЛИ X — родитель Y и женщина
```

> **Совет:** точку с запятой лучше использовать осторожно и с скобками, потому что приоритет `,` выше, чем `;`. Запись `a, b ; c, d` читается как `(a, b) ; (c, d)`.

## 5. Каковы особенности использования переменных в Prolog?

1. **Переменные начинаются с заглавной буквы или символа `_`** (`X`, `Y`, `Parent`, `_Temp`). Атомы (константы) начинаются со строчной буквы (`ivan`) или записываются в апострофах (`'Иван'`).
2. **Переменная не имеет типа** — она может быть связана с чем угодно: числом, атомом, списком, структурой.
3. **Переменная локальна в пределах одного предложения.** Одноимённые переменные в разных предложениях — разные переменные.
4. **Переменные не присваиваются, а унифицируются.** Связывание происходит при сопоставлении с фактами и головами правил.
5. **Переменная может быть свободной или связанной.** Свободная — без значения; связанная — с конкретным значением.
6. **Одна и та же переменная в одном предложении обозначает один и тот же объект.** Например, в `parent(P, X), parent(P, Y)` переменная `P` — один и тот же родитель для `X` и `Y`.
7. **Переменные могут быть пересвязаны при поиске с возвратом.** Если доказательство пошло по неверному пути, Prolog «откатывает» связывание.

## 6. Для чего нужны анонимные переменные?

**Анонимная переменная** — это переменная с именем `_` (одиночный символ подчёркивания).

Она нужна, когда **значение переменной не важно** и не будет использоваться. Каждое вхождение `_` — это **новая, независимая** переменная. Если написать `_X` (с подчёркиванием в начале, но с именем), это будет обычная переменная, просто без предупреждения о singleton-переменной.

Пример:

```prolog
% Нас интересует только факт, что у кого-то есть родитель, но не имя родителя
has_parent(X) :- parent(_, X).

% В правиле «есть мужчина-родитель» имя ребёнка не важно
is_father(X) :- man(X), parent(X, _).
```

Без `_` пришлось бы вводить фиктивное имя (`Parent`, `Child`), которое не используется.

## 7. Как выполнить присваивание в программе на Prolog?

**Присваивания в привычном смысле в Prolog нет.** Есть три родственных механизма:

1. **Унификация `=`** — сопоставление двух термов. Если один из них переменная, она связывается со вторым.

```prolog
?- X = 5.
X = 5.

?- X = Y, Y = 5.
X = 5, Y = 5.
```

2. **Арифметическое вычисление `is/2`** — вычисляет выражение справа и унифицирует результат с левой частью. Левая часть должна быть свободной переменной или числом.

```prolog
?- X is 2 + 3.
X = 5.

?- X is 2 * 3 + 1.
X = 7.
```

3. **Связывание при доказательстве цели** — переменная конкретизируется при сопоставлении с фактом или головой правила.

```prolog
?- word('кот', X).
X = [cat, tomcat].
```

> **Важно:** `=` — это унификация, а не присваивание. `X = 5, X = 6` потерпит неудачу, потому что `X` уже связано с `5`.

## 8. Перечислите основные правила поиска с возвратом.

Четыре правила (из методички, стр. 18):

1. **Правило 1.** Подцели должны быть согласованы **по порядку, слева направо** (сверху вниз по дереву целей).
2. **Правило 2.** Предикатные предложения проверяются **в том порядке, в котором они появляются в программе**, сверху вниз.
3. **Правило 3.** Когда подцель сопоставляется с заголовком правила, **тело этого правила должно быть доказано**. Тело, в свою очередь, состоит из новых подцелей.
4. **Правило 4.** Целевое утверждение считается согласованным, когда **для каждой листовой вершины дерева целей найдены соответствующие факты**.

## 9. Опишите особенности конкретизации переменных значениями в процессе поиска с возвратом.

- Переменная **конкретизируется** (связывается со значением) в момент успешной унификации с фактом или головой правила.
- Если позже доказательство терпит неудачу, Prolog **откатывает** конкретизацию: переменная снова становится свободной.
- При возврате Prolog ищет **следующее** подходящее предложение и пытается конкретизировать переменную иначе.
- Переменная может получить несколько значений **последовательно** — при переборе решений. Пользователь нажимает `;` для запроса следующего решения.
- Конкретизация **локальна** в пределах текущей ветви дерева целей.

Пример:

```prolog
word('дом', ['house', 'home', 'building']).
word('кот', ['cat', 'tomcat']).

?- word(Ru, En).
Ru = 'дом', En = [house, home, building] ;   % первое решение
Ru = 'кот', En = [cat, tomcat].              % второе решение (после ;)
```

## 10. Что такое точка возврата?

**Точка возврата (backtrack point)** — это место в дереве доказательства, куда Prolog может вернуться, если текущая ветвь потерпела неудачу.

Точки возврата возникают:

- при наличии **нескольких предложений** с одинаковым именем и арностью (Prolog может попробовать следующее, если текущее не подошло);
- при наличии **нескольких решений** у подцели (например, `word/2` может дать несколько фактов);
- при использовании **дизъюнкции `;`** — альтернативы создают точки возврата.

Пока в стеке есть точки возврата, Prolog может продолжать поиск. Когда точки возврата исчерпаны, запрос терпит неудачу (`false`).

## 11. Важен ли порядок записи предложений в тексте программы?

**Да, важен.** Prolog проверяет предложения **сверху вниз**, и первое подходящее предложение используется первым. Это влияет на:

- **порядок получения решений** — решения выдаются в том порядке, в котором записаны предложения;
- **эффективность** — если часто используемые факты записаны в начале, программа работает быстрее;
- **семантику в сочетании с отсечением `!`** — отсечение «замораживает» выбор, сделанный на основе порядка;
- **завершаемость рекурсивных правил** — граничное условие должно стоять перед рекурсивным вызовом, иначе будет бесконечная рекурсия.

Пример: если поменять местами `handle_choice(_)` и `handle_choice(1)`, то меню перестанет работать — «ловушка» перехватит все запросы.

---

## 12. На что влияет порядок записи предложений?

1. **Порядок выдачи решений.** Prolog выдаёт решения в порядке перебора предложений.
2. **Эффективность поиска.** Ранние предложения проверяются раньше, и если они часто срабатывают, поиск ускоряется.
3. **Корректность рекурсии.** Граничное условие должно стоять первым, иначе рекурсия не остановится.
4. **Работа отсечения `!`.** Отсечение отсекает точки возврата, и порядок предложений определяет, что именно отсекается.
5. **Работа «ловушек».** Предложение-ловушка (`handle_choice(_)`, `r(_) :- ...`) должно стоять последним, иначе оно перехватит все запросы.

## 13. Для чего используется дерево целей?

**Дерево целей (дерево доказательства)** — это графическое представление процесса доказательства запроса. Оно показывает:

- как исходная цель разбивается на подцели;
- какие предложения программы используются на каждом шаге;
- где возникают точки возврата;
- где происходят конкретизации переменных;
- где доказательство терпит неудачу и происходит возврат.

Дерево целей используется для:

- **отладки** — визуально видно, где программа «сворачивает не туда»;
- **объяснения** — преподавателю и студенту понятно, как Prolog пришёл к ответу;
- **анализа эффективности** — видно, сколько лишних ветвей перебирается;
- **понимания поиска с возвратом** — наглядно показаны откаты.

Пример для `factorial(3, FactN)` приведён на стр. 27 методички.

## 14. Назовите условия, необходимые для работы поиска с возвратом.

1. Наличие **точек возврата** — мест, куда можно вернуться.
2. Наличие **альтернатив** — нескольких предложений с одинаковым именем/арностью или нескольких решений у подцели.
3. Наличие **свободных переменных**, которые можно пересвязать при возврате.
4. **Неудача** текущей ветви — только тогда Prolog начинает возврат.
5. Сохранение **состояния стека** — Prolog должен помнить, какие переменные были связаны и какие точки возврата остались.

Если все переменные связаны и альтернатив нет — возврат невозможен, и запрос либо успешен, либо терпит неудачу.

## 15. Какие встроенные средства существуют для управления поиском с возвратом?

1. **`fail/0`** — всегда терпит неудачу. Используется для **принудительного возврата** (например, в цикле вывода всех фактов).
2. **`!/0` (отсечение)** — убирает все точки возврата, накопленные с момента вызова предиката. Предотвращает возврат.
3. **`repeat/0`** — всегда успешен, но оставляет точку возврата. Используется для организации циклов.
4. **`true/0`** — всегда успешен, точки возврата не создаёт.
5. **`not/1` или `\+/1`** — отрицание как неудача: `\+ Goal` успешно, если `Goal` терпит неудачу.
6. **`once/1`** — доказывает цель только один раз (первое решение), отсекает остальные.
7. **`call/1`** — вызывает цель, переданную как терм.
8. **`forall/2`** — «для всех»: `forall(Cond, Action)`.

## 16. Можно ли обеспечить равноценную замену встроенного предиката `fail/0`?

**Полной равноценной замены нет**, потому что `fail/0` — это встроенный предикат, который всегда терпит неудачу и не создаёт точек возврата. Но можно эмулировать его поведение:

- **`1 = 2`** — всегда ложно, потому что 1 не унифицируется с 2. Создаёт неудачу, как `fail`.
- **`false`** — встроенный синоним `fail` в SWI-Prolog.
- **`X = 1, X = 2`** — тоже всегда ложно, но с лишними унификациями.
- **`\+ true`** — успешно тогда и только тогда, когда `true` терпит неудачу, т.е. всегда ложно.

Однако эти замены **не полностью эквивалентны** `fail/0`:

- Они могут оставлять **точки возврата**, которых у `fail` нет.
- Они могут быть **медленнее**.
- Они могут **не работать** в некоторых контекстах (например, внутри `\+`).

Практический вывод: **используйте `fail/0`**, а не самодельные замены.

## 17. Можно ли и имеет ли смысл записывать цели после цели `fail`?

**Синтаксически можно**, но **семантически бессмысленно**. `fail` всегда терпит неудачу, поэтому все цели после него в этом же предложении **никогда не будут выполнены** — Prolog сразу начинает возврат.

Пример:

```prolog
bad_rule :- write('до'), fail, write('после').
```

Запрос `?- bad_rule.` выведет только `до`, а `после` — никогда. Это классическая ошибка начинающих.

**Единственный случай, когда цель после `fail` имеет смысл** — если она находится в **другом предложении** того же предиката. Например:

```prolog
print_all :-
    word(Ru, En),
    write(Ru), write(' -> '), write(En), nl,
    fail.
print_all.       % это предложение без тела — сработает после fail
```

Здесь `print_all.` — **отдельное предложение**, а не цель после `fail` в том же теле. Оно и обеспечивает успешное завершение запроса.

## 18. В соответствии с какими правилами следует использовать предикат отсечение `!`?

1. **Отсечение ставится после проверок, которые должны быть «заморожены».** Например, после проверки граничного условия рекурсии:

```prolog
factorial(0, 1) :- !.
factorial(N, FactN) :- M is N-1, factorial(M, FactM), FactN is FactM * N.
```

2. **Отсечение не должно менять декларативный смысл предиката.** Если убрать `!` и результат не изменится (только станет менее эффективным) — это **зелёное отсечение**.
3. **Отсечение не должно использоваться для «латания» логических ошибок.** Если без `!` предикат даёт неверные решения — это **красное отсечение**, и его лучше избегать.
4. **Отсечение ставится в начале тела, если нужно выбрать только первое подходящее предложение.** Например, в детерминированных предикатах.
5. **Отсечение не должно отсекать точки возврата, которые могут понадобиться.** Например, если предикат должен давать несколько решений — `!` в нём неуместен.
6. **Документируйте отсечения.** Комментарий `% отсечение: ...` помогает понять, зачем оно нужно.

## 19. Какова роль предиката отсечение `!` при организации ветвления с помощью нескольких правил вывода?

Отсечение позволяет реализовать **детерминированное ветвление** — выбор **только одного** правила из нескольких, даже если другие тоже могли бы подойти.

Пример:

```prolog
r(1) :- !, write('первое правило').
r(2) :- !, write('второе правило').
r(3) :- !, write('третье правило').
r(_) :- write('ловушка').
```

- Если запрос `?- r(1).`, сработает первое правило, `!` отсечёт остальные, и Prolog не будет пробовать `r(2)`, `r(3)`, `r(_)`.
- Если запрос `?- r(5).`, первые три правила не подойдут, сработает `r(_)` — «ловушка».

Без отсечения Prolog после первого успешного правила всё равно оставил бы точки возврата и при запросе `;` попробовал бы остальные. Отсечение делает предикат **детерминированным**: одно правило — один ответ.

Это особенно полезно, когда правила **взаимоисключающие** (например, «положительное число», «ноль», «отрицательное число»), и нужно, чтобы сработало ровно одно.

## 20. В чем разница между зелёным и красным отсечениями?

| Признак | Зелёное отсечение | Красное отсечение |
|---|---|---|
| Влияние на декларативный смысл | Не меняет | Меняет |
| Результат при удалении `!` | Тот же (только медленнее) | Другой (появляются лишние решения) |
| Назначение | Повышение эффективности | Исправление логики |
| Рекомендация | Использовать | Избегать |
| Пример | `factorial(0,1) :- !.` | `max(X,Y,X) :- X >= Y, !.` (без `!` при `X = Y` будет два решения) |

**Зелёное отсечение** — «безопасное». Оно лишь убирает заведомо ненужные точки возврата, не влияя на множество решений. Пример: в факториале после `N = 0` другие правила всё равно не подойдут, и `!` просто экономит время.

**Красное отсечение** — «опасное». Оно **меняет** множество решений: без него предикат давал бы больше ответов. Пример:

```prolog
max(X, Y, X) :- X >= Y, !.
max(_, Y, Y).
```

При `X = Y` без `!` было бы **два** решения (`X` и `Y`), а с `!` — одно. Это красное отсечение.

**Правило хорошего стиля:** старайтесь, чтобы все отсечения в программе были зелёными. Красные отсечения делают программу хрупкой и трудной для понимания.

## 21. Как организовать поиск с возвратом, если отсутствуют цели, которые можно передоказать?

Если **нет точек возврата** (все переменные связаны, альтернатив нет), обычный поиск с возвратом невозможен. Чтобы его организовать, используют:

1. **`fail/0`** — принудительно терпит неудачу, заставляя Prolog вернуться к предыдущей цели. Классический приём:

```prolog
print_all :-
    word(Ru, En),
    write(Ru), write(' -> '), write(En), nl,
    fail.
print_all.
```

Здесь `word/2` создаёт точки возврата, а `fail` заставляет перебирать все факты.

2. **`repeat/0`** — создаёт бесконечную точку возврата:

```prolog
loop :-
    repeat,
    write('Введите команду: '),
    read(Cmd),
    process(Cmd),
    Cmd = exit.
```

`repeat` всегда успешен, но оставляет точку возврата. Когда `Cmd = exit` терпит неудачу (или, наоборот, успешен — в зависимости от логики), происходит возврат к `repeat`.

3. **Рекурсия** — если нужно перебрать элементы списка, рекурсивный вызов сам создаёт точки возврата.

4. **`forall/2`** — `forall(Cond, Action)` выполняет `Action` для всех решений `Cond`:

```prolog
print_all :-
    forall(word(Ru, En), (write(Ru), write(' -> '), write(En), nl)).
```

Здесь `forall` сам организует перебор, и `fail` не нужен.

## 22. Как работает встроенный предикат `repeat/0`?

`repeat/0` — это предикат, который **всегда успешен** и **оставляет точку возврата**. Его поведение эквивалентно определению:

```prolog
repeat.
repeat :- repeat.
```

Разберём:

- Первое предложение `repeat.` — факт. При первом вызове `repeat` успешно завершается.
- Второе предложение `repeat :- repeat.` — правило. При возврате Prolog может выбрать это правило и снова вызвать `repeat`, что даёт **бесконечную цепочку успехов** с точками возврата.

**Применение:** организация циклов, которые завершаются по условию внутри тела.

```prolog
main_loop :-
    repeat,
    write('Введите число (0 — выход): '),
    read(N),
    (   N = 0
    ->  !
    ;   write('Вы ввели: '), write(N), nl,
        fail
    ).
```

- `repeat` создаёт точку возврата.
- Если `N = 0` — `!` отсекает точку возврата, цикл завершается.
- Иначе — `fail` возвращает управление к `repeat`, и цикл повторяется.

**Важно:** без отсечения `!` или условия выхода `repeat` создаст **бесконечный цикл**. Поэтому `repeat` всегда используют вместе с `!` или с целью, которая при выполнении отсекает точку возврата.

**Альтернатива:** в SWI-Prolog часто вместо `repeat` + `fail` используют рекурсивный вызов предиката (`main_loop :- ... , main_loop.`), что читается легче и не требует отсечения.
